# Бриф Promo Experience — PRODIGI AGENCY

Интерактивная анкета для клиентов: приветствие → 6 этапов → контакты → проверка → отправка.
Ответы уходят письмом на почту Prodigi и сохраняются в базе данных, файлы — в закрытом хранилище.

- Интерфейс: чистый HTML/CSS/JS без сборки (`public/`).
- Сервер: две функции `/api/submit` и `/api/upload-url` (`server/`), работают на Netlify и Vercel.
- Почта: [Resend](https://resend.com). База и файлы: [Supabase](https://supabase.com). Оба сервиса имеют бесплатный тариф.
- Ключи хранятся только в переменных окружения сервера и никогда не попадают в браузер.

## Как всё устроено

| Что | Где |
|---|---|
| Этапы, вопросы, поля, варианты ответов | `public/js/config/brief.js` |
| Все тексты интерфейса и письма (русский) | `public/js/config/locales/ru.js` |
| Добавить язык (hy, en) | скопировать `ru.js` → `hy.js`, перевести, подключить в `locales/index.js` |
| Проверка ответов (общая для браузера и сервера) | `public/js/core/validate.js` |
| Экраны и компоненты полей | `public/js/app.js`, `public/js/ui/fields.js` |
| Приём брифа, база, письмо | `server/submit.js`, `server/supabase.js`, `server/resend.js`, `server/email.js` |
| Таблицы и хранилище | `supabase/schema.sql` |

Чтобы поменять вопрос или вариант ответа, достаточно поправить `brief.js` и текст в `ru.js`.
Интерфейс, проверка, экран проверки и письмо подстроятся сами.

## Что происходит при отправке

1. Браузер проверяет поля и отправляет ответы на `/api/submit`.
2. Сервер ещё раз проверяет всё сам, отсеивает ботов (скрытое поле, слишком быстрое заполнение, не больше 5 брифов в час с одного IP, запросы только со своего сайта).
3. Бриф сохраняется в таблицу `briefs`.
4. Письмо «Новый бриф Promo Experience — [бренд]» уходит на почту Prodigi. «Ответить» в письме пишет контактному лицу клиента.
5. Только после успешной отправки письма клиент видит экран «Спасибо!». При любой ошибке ответы остаются на месте, клиент может нажать «Попробовать ещё раз», повтор не создаёт дубликат.

Файлы загружаются сразу при выборе: сервер проверяет тип и размер и выдаёт одноразовую ссылку, файл уходит прямо в закрытый бакет Supabase. В письме — ссылки на скачивание (действуют 30 дней), сами файлы остаются в Supabase → Storage → `brief-files`.

## Настройка (один раз, ~20 минут)

### 1. Supabase — база и файлы

1. Зарегистрируйтесь на [supabase.com](https://supabase.com) и создайте проект (регион ближе к клиентам, например Frankfurt).
2. Откройте **SQL Editor → New query**, вставьте содержимое `supabase/schema.sql`, нажмите **Run**.
3. Откройте **Project Settings → API** и скопируйте:
   - **Project URL** → `SUPABASE_URL`
   - ключ **service_role** (секретный) → `SUPABASE_SERVICE_ROLE_KEY`

Присланные брифы смотреть в **Table Editor → briefs**, файлы — в **Storage → brief-files**.

### 2. Resend — отправка писем

1. Зарегистрируйтесь на [resend.com](https://resend.com).
2. **Domains → Add Domain**: добавьте домен Prodigi и пропишите DNS-записи, которые покажет Resend (обычно 3 записи у регистратора домена). Дождитесь статуса **Verified**.
3. **API Keys → Create API Key** (права Sending access) → `RESEND_API_KEY`.
4. Придумайте адрес отправителя на этом домене, например `Prodigi Brief <brief@ваш-домен>` → `BRIEF_EMAIL_FROM`.
5. Рабочая почта, куда приходят брифы → `BRIEF_EMAIL_TO` (можно несколько через запятую).

Пока домен не подтверждён, Resend разрешает отправлять только с `onboarding@resend.dev` и только на почту владельца аккаунта Resend. Для проверки этого достаточно.

### 3. Публикация

**Netlify**
1. Add new site → Import from Git → репозиторий `promo_mvp`.
2. **Base directory:** `brief`. Build command пустой, Publish directory `brief/public` (подставится из `netlify.toml`).
3. **Site configuration → Environment variables:** добавьте переменные из `.env.example`.
4. Deploy. Затем **Domain management → Add a domain**, например `brief.prodigi.am`.

**Vercel**
1. Add New → Project → репозиторий `promo_mvp`.
2. **Root Directory:** `brief`. Framework Preset: Other.
3. **Environment Variables:** переменные из `.env.example`.
4. Deploy. Затем **Settings → Domains** для своего домена.

После изменения переменных окружения сделайте повторный деплой.

### Переменные окружения

| Переменная | Обязательна | Что это |
|---|---|---|
| `RESEND_API_KEY` | да | ключ Resend |
| `BRIEF_EMAIL_TO` | да | куда приходят брифы |
| `BRIEF_EMAIL_FROM` | да | отправитель на подтверждённом домене |
| `SUPABASE_URL` | да | адрес проекта Supabase |
| `SUPABASE_SERVICE_ROLE_KEY` | да | секретный ключ Supabase |
| `SUPABASE_BUCKET` | нет | бакет для файлов, по умолчанию `brief-files` |
| `ALLOWED_ORIGINS` | нет | дополнительные домены, с которых можно отправлять бриф |
| `IP_HASH_SALT` | нет | любая случайная строка (IP хранится только в виде хэша) |
| `MIN_FILL_SECONDS` | нет | минимальное время заполнения, по умолчанию 20 |
| `MAX_SUBMISSIONS_PER_HOUR` | нет | брифов в час с одного IP, по умолчанию 5 |
| `FILE_LINK_DAYS` | нет | сколько дней действуют ссылки на файлы в письме, по умолчанию 30 |

Пока переменные не заданы, бриф можно заполнить, но при отправке клиент увидит честное сообщение «Отправка временно недоступна, ответы сохранены», а не ложный успех.

## Локальный запуск

```bash
cd brief
cp .env.example .env   # и впишите ключи
npm run dev            # http://localhost:8787
npm test               # проверки сервера на заглушках Supabase и Resend
```

Нужен Node.js 18 или новее, внешних зависимостей нет.
